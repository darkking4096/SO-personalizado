# Story 1.3: Create Time-Based Wallpaper Scheduler

## Summary
Implement time-based wallpaper scheduling allowing users to create schedules where wallpapers change at specific times (30-minute granularity). Users can define multiple schedules and the system auto-transitions wallpapers.

## Acceptance Criteria

- [x] UI: Schedule builder with time picker (30-minute granularity)
- [x] Create multiple schedules: Start time → Wallpaper image
- [x] Time picker: Native or custom widget supporting 00:00-23:59 format
- [x] Auto-transition: System changes wallpaper at scheduled times (background service)
- [x] Scheduler persists to store and profile (JSON serializable)
- [x] Tolerance: Transitions within ±5 minutes of scheduled time
- [x] Service: `scheduleWallpaper(time: string, imagePath: string)` method (+ full scheduler API)
- [x] Service: Background job runs continuously checking scheduled times
- [x] Error handling: Handle missing image files, invalid times gracefully
- [x] Performance: <1% CPU during idle waiting for schedule (using setInterval)
- [x] TypeScript types for Schedule: `{ time: string; imagePath: string; enabled: boolean }`
- [x] Unit tests for scheduler logic (63 tests, 100% passing)

## Technical Approach

**Components:**
- `src/components/ScheduleBuilder.tsx` — Time picker + wallpaper selector + list of schedules
- `src/components/TimePickerWidget.tsx` — Time input (30-min granularity)

**Services:**
- `src/services/wallpaperService.ts`:
  - `scheduleWallpaper(time: string, imagePath: string)` → Add schedule
  - `removeSchedule(scheduleId: string)` → Remove schedule
  - `getSchedules()` → Retrieve all schedules
  - `startScheduler()` → Begin background scheduler
  - `stopScheduler()` → Stop background scheduler

**Background Job:**
- Use `node-cron` or custom interval-based scheduler
- Every 1 minute: check if current time matches any schedule
- On match: apply wallpaper asynchronously
- Log transitions for debugging

**Store (`src/stores/wallpaperStore.ts`):**
- `schedules: Schedule[]`
- `currentScheduleId: string | null`

## Technical Notes

1. **Time Format:** Use 24-hour format (HH:MM) with 30-minute granularity
2. **Background Scheduler:** Start in Electron main process for persistence across window close
3. **Performance:** Use native `setInterval()` rather than heavy job queue for simplicity
4. **Edge Cases:** Handle schedule at midnight, DST transitions, system time changes
